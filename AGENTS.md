# SpiritCal — agent context

Read this first. It exists so any future prompt is productive without re-reading the whole repo.

## What this is
**SpiritCal**: a free, fun, Earthtone-themed **character stat calculator** for the game **SpiritVale**.
Made by the YouTube channel **KRUN-KID**. No accounts, no backend, no paywalls — keep it that way.

## Stack
Next.js (App Router) + TypeScript + Tailwind CSS v4. 100% client-side; deploys on Vercel (`npm run dev` / `build`).

## Source of truth for game math
The dev's real formulas + element chart live in `mechanics/` (`formulas.md`, `SpiritVale_Elements.png`, `stances.md`).
They are encoded in exactly TWO files:
- `src/data/gameData.ts` — constants: 10 elements + `EFFECTIVENESS` matrix, weapon Base Attack Delay, archetype HP%, status effects/resist, stances (`STANCES` + `getStance()`), `DEFAULT_DAMAGE`, defaults.
- `src/lib/formulas.ts` — pure functions ported 1:1 from `formulas.md`; `computeCore()`, `computeSpeed()`, `computeCrit()`, `computeDefense()`, `computeUtility()`, `computeDamageBreakdown()`, and `computeStats()` (labelled stat sheet + formula text — calls the other `compute*` functions rather than recomputing inline, so the sheet can never drift from the sections). Does NOT contain `applyDeltas` or any UI-model helpers — those live in `src/lib/setCompare.ts`.

> To change game data/math, edit ONLY those two files (and `mechanics/` if the source changed). Formulas are ported verbatim — keep `FLOOR`/`ROUND` semantics and percent-as-whole-number (10 = 10%) convention.

## Tabs
1. **Calculator** — five focused sections (Total Attack, Attack & Cast Speed, Critical, Defense, Utility). Deliberately has NO full stat sheet and no raw input form; those live in Build Compare.
2. **Gear Compare** — gear-swap impact tool. (Internal tab id is `setcompare`; the nav label is "Gear Compare". Do not rename the id or the `SetCompare.tsx` file — only the label changed.) Add one card per piece of gear you are considering changing. Each card has its own Removing and Adding stat sections, a swap name, an enable toggle, and a DPS chip (computed in isolation — that card alone vs. baseline, regardless of the toggle). Active cards contribute to the combined net delta; toggled-off cards are excluded. The combined result table shows only stats that actually changed. State is session-only, not persisted.
3. **Damage** — Target & Element plus four switchable damage sources (AA, Skills, Status, Autocast) each with named multiplicative multipliers. Skills are a list with per-skill cast time and cooldown driving a rotation. Reads shared ATK/speed/crit live from the same build.
4. **Presets** — saved build presets. Has a Backup JSON / Restore JSON pair that exports all build presets plus all gear loadouts into one file. Restore is always additive (fresh UUIDs). Auto-save to localStorage continues as before.
5. **Essence** — item substat reference plus the Potential modification system. The tab is divided into five `SectionCard` sections; only the first is open by default. Order: (1) Potential Simulator (open) — tap-to-count essence tiles with starting-potential picker and remaining-range result; (2) Essence Types — five orb reference cards; (3) How Equipment Substats Roll — roll rules; (4) Substat Pools by Slot — base-stat banner plus nine pool cards; (5) Where to Find Each Modifier — reverse-lookup table. An "Expand all / Collapse all" toolbar button matches the Calculator and Damage tabs. The component is stateful (section open state + simulator counts). Data in `src/data/essenceData.ts` and `src/data/potentialData.ts`.
6. **Reference** — element chart, stances, status effects.
7. **Loadout** — gear simulator. 10 equipment slots + 4 artifact slots, each with a substat editor. Items start at 3 substats; armor/accessories expand to 5, weapons expand to 6, artifacts stay at 3. The 5th/6th substat repeats a pool row. Multiple named sets supported with localStorage persistence, plus a per-stat delta comparison view. No "transfer to Calculator" button — stats from gear and base attributes intertwine and are not directly substitutable.
8. **Build Compare** — side-by-side build comparison. Also the only place with the full `BuildForm` (every attribute, gear flat/percent, target) and the complete `computeStats()` table, so it doubles as the stat sheet.

## DamageConfig structure
`Build.damage: DamageConfig` is persisted with presets and share links. `normalizeDamage()` in `storage.ts` deep-merges it, defaults every `enabled` to true, and migrates the legacy singular `skill` object into `skills.entries`. Defaults are `DEFAULT_DAMAGE` / `DEFAULT_SKILL` in `gameData.ts`.

```ts
DamageConfig {
  aa:       { enabled, multipliers: DamageMultiplier[] }
  skills:   { enabled, entries: SkillEntry[] }
  status:   { enabled, stacks, critApplies, multipliers }
  autocast: { enabled, name, damagePct, chancePct, critApplies, attackType: SourceAttackType, multipliers }
}
SkillEntry { id, name, damagePct, hits, critApplies, multistrikeApplies, attackType: SourceAttackType, baseCastTime, cooldownSec, enabled, multipliers }
```

`SourceAttackType = "melee" | "ranged" | "magic" | "weapon"`. `"weapon"` follows the equipped main-hand type at compute time. Magic skills use `skillAtkByType.magic` (scales INT, reads flat MATK); melee/ranged use `skillAtkByType.melee/ranged` (scale STR/DEX, read flat ATK). Skills and autocast use the **same summing rule as autoattacks** — see the dual wield entry under Confirmed mechanics. Target defense is resolved per source: magic hits enemy MDEF, melee/ranged hits DEF.

Every source can be switched off (some classes have no autocast). **Autocast is coupled to AA**: `autocastOn = autocast.enabled && aa.enabled`, because `formulas.md` says only autoattacks trigger autocasts. `computeDamageBreakdown` exposes `autocastSuppressedByAa` for the UI to explain it.

## Rotation model
Skills form a real timeline. Each has `cycle = actualCastTime + skillDelaySec + max(0, cooldownSec)` (all three are additive; cooldown starts when the cast completes) and claims `castFraction = actualCastTime / cycle` of the timeline. Two limits apply and the tighter wins: the timeline (`isCastBound`, skills want over 100% of the time) and skill delay (`isDelayBound`, combined casts/sec exceed `1 / skillDelaySec`). `aaUptime` is whatever the resolved cast rates leave free; AA and autocast scale by it while status ticks regardless. Full detail in `mechanics/damage-estimate.md`.

## Confirmed mechanics
- **Autocast + Multistrike**: dev-confirmed that Multistrike extra hits do NOT trigger autocast (`formulas.md`: "Multihits don't increase autocast chances, they are counted as one hit"). Procs scale on base attacks/sec, not effective hits/sec. Do not reintroduce a proc-basis toggle.
- **Per-skill Multistrike**: some skills' tooltips say "Triggers Multistrike". When toggled on via `SkillEntry.multistrikeApplies`, the skill's hit count is multiplied by `avgHitsPerAttack = 1 + Multistrike%/100`, exactly like autoattacks. Timing (cycle, casts/sec) is unaffected. Defaults to `false`; do not enable it for skills whose tooltip does not mention it.
- **Skill delay (corrected Aug 2026)**: the in-game "Skill delay" stat tracks ASPD, not Cast Speed. The dev has not published the formula, so the app takes it as a **manual input** (`Build.skillDelaySec`, default 0.3) read from the in-game stat window. Cast Speed only drives **CTR** (cast time multiplier = `(200 - CastSpeed) / 50`). The skill delay tile in SpeedSection is now a `NumberInput`. Do not re-derive skill delay from Cast Speed. The old analysis assuming they were the same number is preserved in `mechanics/skill-delay.md` under "Historical note". Open assumption: the delay gates skills only, not autoattacks.
- **CTR cap (confirmed Aug 2026)**: Cast Time Reduction is hard-capped at **90%** — you always pay at least 10% of a skill's listed cast time. `CastTime` is floored at `0.10` in `computeSpeed`. Cast Speed 195 exactly hits the cap; any higher value is wasted. The constant `CTR_CAP_PCT = 90` lives in `gameData.ts`. Unlike `AspdLimit`, this cap is not currently raisable by gear. Do not remove the floor or change the cap value without dev confirmation.
- **Stance bonus**: only Two-Handed (empty off-hand) grants a stance bonus, +25% ATK/MATK. One-Handed (shield) grants NO bonus (`mult: 1.0`) — the previously-used +15% figure came from community guides and was disproven by an in-game check, Jul 2026. Do not restore +15% for One-Handed.
- **Dual wield ATK (confirmed Aug 2026)**: the game shows two separate attack totals — one per weapon. Each weapon runs the full attack formula independently using its own flat ATK (`WeaponATK` / `OffhandATK`) and its own attack type. Shared terms (LV/4, primary stat scaling, MASTERY, ATK%) count in both. `attackByType = mainAtk + offAtk`. This is why dual wield has no stance multiplier. `GearMods.ATK` is now **non-weapon flat ATK only** (armor, accessories, buffs). `GearMods.WeaponATK` is the main-hand weapon's ATK, `GearMods.OffhandATK` is the off-hand weapon's ATK. Old presets default both weapon fields to 0, so single-weapon totals are unchanged. MATK mirrors the same three-way split: `GearMods.MATK` (non-weapon), `GearMods.WeaponMATK` (main hand), `GearMods.OffhandMATK` (off hand). The magic formula uses the MATK pool; melee/ranged use the ATK pool. Dev-confirmed Aug 2026 that dual wielding magic weapons shows **two MATK values** in the stat window, exactly as physical dual wield shows two ATK values. Old saves with a magic weapon are migrated: `WeaponATK` → `WeaponMATK` when `WeaponMATK` is absent and the weapon type is magic.
- **Skill / autocast ATK (corrected Aug 2026)**: skills use the SAME summing rule as autoattacks — `c.skillAtkByType[type]` runs the full attack formula once per equipped weapon **whose own type matches** the skill, then sums. Two pistols casting a ranged skill get two runs summed (identical to the autoattack total). When no equipped weapon matches the type, it is a single run off non-weapon flat stats — two pistols casting a magic skill get one INT-driven run off gear MATK, because a pistol carries no MATK. `c.skillWeaponRunsByType` reports the run count so the UI can print "(2 weapons)". Do NOT reintroduce the single-pooled-run model that counted shared terms (LV/4, MASTERY, stat scaling) once; it roughly halved dual wield skill damage and was disproven in-game.
- **Siphon is TWO separate per-hit stats**, `SiphonHp` and `SiphonMp` (`GearMods`), not one shared `Siphon` value — that was a modeling error, corrected Jul 2026 (see `mechanics/formulas.md`). Siphon is flat per hit, and multistrike extra hits each siphon, so siphon-per-second scales with `computeSpeed().effectiveHitsPerSec` — the OPPOSITE of the autocast rule. Do not reintroduce a single-stat model.
- **Reflect formula (confirmed Jul 2026)**: `(LV + totalDEF/2 + flatDEF/2 + computedATK/2) * 4 * Reflect%`. The two DEF terms are: `c.def` (total DEF, scaled by VIT+Def%) and `g.DEF` (the raw flat DEF gear input, unscaled). ATK is `c.attackByType` — full computed melee/ranged/magic attack for the equipped weapon. The old `FlatDEF` field in `GearMods` has been removed; `g.DEF` covers both roles. `normalizeGear()` drops stale `FlatDEF` / `Siphon` keys from old presets by constructing result from `DEFAULT_GEAR` keys only.
- **Leech is TWO separate stats**, `LeechHppct` and `LeechMppct` (`GearMods`), each with its own raw value and 20% cap (confirmed Jul 2026). MP Leech does not appear on any in-game gear yet — its input exists at 0 with a hint, ready for when the game ships it. Old presets with `Leechpct` migrate to `LeechHppct` only in `normalizeGear`. Do not merge them back into a shared stat.
- **Magic damage reduction** uses the same formula as physical: `100 / (MDEF + 100)` (confirmed Jul 2026). Already implemented correctly.
- **Loadout substat counts (confirmed Jul 2026, clarified Aug 2026)**: All items start at 3 substats. Normal max: weapons 5, armor/accessories 4, artifacts 3. The **Essence of Chaos** can push weapons to 6 and armor/accessories to 5 by adding one extra substat (which may duplicate a row). The Loadout editor hard-caps at the Chaos-extended ceiling (6/5/3) to allow entry of Chaos-boosted items. `normalMaxSubstats` in `essenceData.ts` holds the normal ceiling; `maxSubstats` holds the Chaos ceiling. Do not collapse these into one value. The 5th substat on fully-upgraded armor (or the 6th on a weapon) repeats a row from that slot's pool. Pool rows for tiers 2..N are drawn in random order with no repeats until that final expansion tier.
- **Loadout gear name**: `LoadoutSlot.name` is an optional free-text label for the specific item (e.g. "Dragon Helm +7"). Empty falls back to the slot label everywhere. Migrated via `normalizeLoadoutSet` (backfills `name: ""`).
- **Loadout JSON export shape**: `{ app: "spiritcal", kind: "loadouts", version: 1, exportedAt: ISO string, sets: LoadoutSet[] }`. `parseLoadoutsFile` also accepts a bare array or a `kind: "backup"` file (pulls only `loadouts`). Import is always additive — sets get fresh UUIDs so nothing is overwritten. Functions live in `storage.ts`: `exportLoadoutsToFile(sets)`, `parseLoadoutsFile(text)`.
- **Backup file shape** (from the Presets tab): `{ app: "spiritcal", kind: "backup", version: 1, exportedAt: ISO string, presets: Build[], loadouts: LoadoutSet[] }`. `exportBackupToFile(presets)` calls `loadLoadouts()` internally. `parseBackupFile(text)` is a tolerant reader that accepts a backup payload, a loadouts payload, a bare `Build[]`, a bare `LoadoutSet[]`, or a single `Build` object — both `presets` and `loadouts` arrays are returned (may be empty). `appendLoadouts(sets)` writes imported loadouts to localStorage. Restore is always additive.
- **Multistrike** (formerly "Double Attack"): renamed by the dev — same stat, same formula. Updated in `essenceData.ts` and `mechanics/essence.md`. `GearMods.Multistrikepct` was already using the new name.
- **Formula blocks** in Critical, Speed, Defense, and Utility sections are collapsed by default via the `FormulaDetails` primitive in `ui.tsx` (native `<details>`/`<summary>`, no JS state, keyboard accessible).
- **Melee ATK scales flat ATK by STR/200** (confirmed Jul 2026, corrected from earlier DEX/200 transcription). Each attack type now uses its own primary stat: melee → STR/200, ranged → DEX/200, magic → INT/200.
- **MDEF scales by INT/1000** (confirmed Jul 2026, corrected from VIT/1000). Physical DEF still scales by VIT/1000. The Defense section exposes an INT input alongside VIT for this reason. Do not revert either stat to VIT.
